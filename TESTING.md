# Проверка Split 4.0 — этап 4: Share и экспорт результатов

Проверки запускаются из корня репозитория. Node.js 24, Python 3 и headless Chromium; тестовые зависимости установлены вне репозитория по README. Приложение не требует сборки.

```sh
export PLAYWRIGHT_MODULE=/tmp/split-test-tools/node_modules/playwright-core
export AXE_MODULE=/tmp/split-test-tools/node_modules/axe-core
export CHROMIUM_PATH=/usr/bin/chromium
node --test --test-isolation=none tests/core.test.cjs tests/history.test.cjs tests/items.test.cjs tests/reports.test.cjs
python3 -m http.server 8000 --bind 127.0.0.1
# В другом терминале с теми же переменными:
node tests/browser.cjs
node tests/history-browser.cjs
node tests/items-browser.cjs
node tests/navigation.cjs
node tests/share-browser.cjs
node tests/accessibility.cjs
node tests/pwa-update.cjs
```

`SPLIT_URL` задаёт другой адрес сервера. PWA-тест поднимает свой временный сервер, меняет версии в памяти и не изменяет приложение. Для axe используется отдельный контекст `bypassCSP`; в сканированиях позиций отключены анимации/переходы для стабильной проверки статического контраста; функциональные сценарии выполняются с действующей CSP.

Ограничения хранения и стратегия безопасного восстановления описаны в README. Приложение не синхронизирует данные между устройствами и не гарантирует транзакционность строго одновременных записей localStorage. Публикация приложения и merge в main не входят в эту задачу.

Новое ограничение схемы: старый клиент этапа 1 не может редактировать документ версии 5. Для отката используйте отдельную сохранённую копию старой схемы, предварительно экспортировав текущие позиции. Простой режим не изменяет свою математику. Проценты ограничены двумя дробными знаками; ID операций предотвращают повтор только внутри своего расчёта, а не синхронизируют разные устройства.

Денежные модули `core.js`, `items-core.js` и схема/хранилище `history.js` в переработке UI не менялись. Навигационные сканирования выполняются при reduced-motion, а функциональные сценарии проверяют обычные анимации. Снимки длинных страниц показывают фиксированную навигацию в положении viewport; прокрутка проверяется отдельно.

Share API проверен через управляемые browser mocks; настоящий системный выбор получателя, ограничения вложений и сохранение изображения в Photos/Files на физических iPhone/Android требуют ручной проверки. Тест не имитирует доставку сообщения мессенджером. Экспорт и fallback локальны, подключений к сторонним сервисам не добавлено. При очень длинном отчёте PNG делится на страницы; пользователь сохраняет нужные страницы отдельно, системный обмен всеми файлами зависит от `canShare` и лимитов ОС. Математические модули и модель истории на этапе 4 не менялись.

`tests/build.test.cjs` проверяет повторную чистую сборку, точность копирования всех
ссылочных ресурсов HTML/service worker, отсутствие служебных файлов в пакете,
использование локального `webDir` без удалённого сервера и разделение PWA/native service worker.
Всего 49 модульных/сборочных тестов. Браузерные сценарии проверяют собранный `www`,
включая математику, историю, JSON, Share/fallback, темы, доступность, офлайн и обновление PWA.
Это регрессия веб-версии, а не доказательство поведения Android WebView/WKWebView.

Android: требуется успешный `assembleDebug`, проверка подписи через
`$ANDROID_HOME/build-tools/36.0.0/apksigner verify --verbose android/app/build/outputs/apk/debug/app-debug.apk`.

macOS CI собирает Simulator без подписи и сохраняет `.app`; проверки на физическом устройстве остаются ручными.

Перед выпуском на устройствах:

- Чистая установка, первый запуск в авиарежиме, создание обоих типов расчёта и повторный запуск после выгрузки приложения.
- Тема, safe area, вырезы/системные панели, клавиатура и смена ориентации; отсутствие перекрытых кнопок и полей.
- Сохранение имён, копеек, позиций и черновиков; обновление APK с той же подписью через `adb install -r` без потери истории.
- Экспорт/импорт JSON, отмена файлового выбора, повреждённый файл; проверить ограничения WebView, не считать загрузку файла гарантированной.
- Текст/PNG, доступность Web Share/Clipboard и ручного fallback. Системный Share/Files — следующий этап, не установленный плагин.
- На iOS Simulator: установка `.app` через `xcrun simctl install booted <path>/App.app`, запуск `xcrun simctl launch booted io.github.ganzzis.split`, повторный запуск офлайн.

Не очищать данные сайта/приложения при проверке обновлений. JSON-резервная копия нужна перед удалением установки.

### Регрессия перекрытия Share нативной Tab Bar

`tests/ios-chrome.cjs` проверяет синхронизацию динамических, одновременно открытых и удаляемых HTML-диалогов. `tests/native-shell.cjs` проверяет размеры sheet при узком/горизонтальном viewport и клавиатуре, доступность основных действий, передачу выбранной PNG без blob-fetch и отправку подготовленного текста без PNG.

Реальный XCTest получает DEBUG-only подтверждение UIKit `UIView.isHidden` через Capacitor bridge. Скрытие только accessibility больше не даёт ложного успеха. Тест нажимает «Копировать текст» и проверяет результат операции, открывает настоящий OS Share Sheet с четырьмя PNG-страницами, отдельной PNG и подготовленным текстом, проверяет системный предпросмотр, закрывает native popover обычным тапом снаружи и проверяет возврат. Затем раскрывает и прокручивает длинный текст, закрывает HTML-окно и нажимает восстановленную Tab Bar. Дополнительно проверяются переименование с клавиатурой и отмена сброса, смены режима и удаления.

Для WebView одного `isHittable` недостаточно: UIKit overlay и внутренний scroll container могут обрезать кнопку. Перед нажатием проверяется её геометрия в свободной области. Внутри Share граница preview учитывает 10 pt верхнего отступа footer; допускается 1 pt округления WK accessibility frames. Дополнительный отступ за последним элементом не требуется.

Simulator CI использует независимые jobs `standard` (iPhone 17 Pro, dark/light и крупный текст) и `compact` (iPhone SE 3, Accessibility XL). На macOS с Xcode 26.3 их можно повторить командами `bash scripts/ios-visual-tests.sh standard` и `bash scripts/ios-visual-tests.sh compact`. Каждый профиль должен запускаться в чистой среде. Это исключает наблюдавшееся зависание simctl при подготовке второго устройства после успешного XCTest. Подготовка/загрузка ограничены тайм-аутами, начальная готовность native chrome ожидается до 90 с на холодном runner. Косметический `status_bar override` не вызывается; время и заряд на скриншотах остаются фактическими.

Скриншоты и xcresult сохраняются в `split-ios-visual-standard-<SHA>` и `split-ios-visual-compact-<SHA>`. DEBUG fixture/probe включаются только явным `--split-ui-tests` и не затрагивают данные пользователя при обычном запуске.

Linux не запускает iOS Simulator: фактическая UI-проверка выполняется macOS CI. Проверка адаптеров не заменяет XCTest. Получатель системного обмена, установка/подпись IPA в GBox и работа на физическом iPhone проверяются пользователем отдельно. Предпросмотр отчёта остаётся в WebView.
