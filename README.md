# Split 4.0

Мобильное приложение для разделения общих расходов с историей расчётов и JSON-резервными копиями. Dark Glass, светлая/тёмная темы, локальное хранение, офлайн-PWA. HTML/CSS/JavaScript без фреймворков, сборки, серверной части и зависимостей приложения.

## Запуск

Из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Для PWA на телефоне требуется HTTPS; localhost подходит для разработки. Поддерживается размещение в подпапке. Целевые браузеры: Safari/iOS 16+ и современные браузеры Android. Реальные устройства требуют ручной проверки.

На iPhone: Safari → «Поделиться» → «На экран “Домой”». На Android: меню Chrome → «Установить приложение» / «Добавить на главный экран». Офлайн доступен после успешной первой загрузки и установки service worker. Шрифты системные, все ресурсы локальные.

## Простой режим

- Внесённые суммы — оплаты общих расходов. Пустая цель равна сумме внесённого. Явный ноль отличается от пустого поля.
- Переводы — **уже выполненные компенсации**. Если Борис должен Анне 500 ₽ и перевёл 200 ₽, остаётся 300 ₽. Выполненная компенсация уменьшает долг отправителя и сумму к получению адресата.
- Все расчёты — в целых копейках. Неразделимый остаток распределяется первым участникам по одной копейке; сумма долей совпадает с расходами. Сводка показывает диапазон долей, карточки — точные значения.
- Недобор и излишек относительно цели представлены отдельными операциями с общей кассой. Детерминированный план погашает балансы, но не гарантирует математически минимальное число переводов.
- Ввод принимает точку/запятую и до двух дробных знаков. Лимиты: 1 млрд ₽ на сумму, 100 участников, 500 переводов. Неверный ввод выделяется, копирование блокируется, сводка явно показывает последние корректные значения.

## Режим «По позициям»

На главном экране выберите режим перед нажатием «Новый расчёт». Все ранее сохранённые расчёты без поля `mode` остаются простыми. Кнопка «Сменить режим» всегда открывает подтверждение: исходный расчёт целиком, включая черновики, сохраняется отдельной копией в истории, а текущий начинает выбранный режим с нулевыми суммами и прежними именами участников. Обе записи сохраняются одной записью истории. Если квоты или места в истории для копии не хватает, смена режима не выполняется. Автоматической конвертации взносов в позиции нет.

В позиции задаются название, сумма, плательщик и получатели расхода. Поддержаны:

- **Поровну**: целые копейки, остаток по одной копейке в порядке участников расчёта, независимо от порядка нажатия флажков.
- **Фиксированные суммы**: сумма долей должна точно совпадать со стоимостью позиции.
- **Проценты**: от 0 до 100%, до двух знаков после запятой, в сумме ровно 100%. Копейки распределяются методом наибольших остатков; при равенстве остатков — в порядке участников. Промежуточные произведения вычисляются через BigInt.

Плательщик может входить или не входить в выбранных участников. Баланс равен сумме оплаченных позиций минус собственные доли, плюс отправленные и минус полученные выполненные компенсации. Взносы и цель простого режима в этот расчёт не попадают. Позиции и переводы ссылаются на ID участников; удаление связанного участника блокируется до изменения/удаления связанных записей и черновиков.

«Изменить расход», «Копировать расход» и «Удалить расход» находятся в карточке позиции. Ввод в редакторе автоматически сохраняется как `expenseDraft`, включая неверные суммы и неполные доли. Корректный черновик сразу включается в предпросмотр итогов; некорректный оставляет в итоге сохранённую версию и показывает предупреждение. Для проведения компенсаций и копирования итогов нужно сохранить расход. Отмена редактирования требует подтверждения. Переход в историю, экспорт и перезагрузка сохраняют открытый черновик. Новую позицию нельзя открыть поверх незаконченной.

В секции «Уже выполненные компенсации» можно внести фактический перевод; его незавершённая форма сохраняется в `paymentDraft`. Кнопка «Отметить выполненным» под предложенным переводом создаёт компенсацию с `operationId`. Повторное проведение той же операции и проведение устаревшего предложения отклоняются. После изменения балансов предложения пересчитываются. Это учёт уже состоявшегося перевода, деньги приложение не переводит. Удаление выполненной компенсации после подтверждения отменяет её учёт.

Лимиты на расчёт: 100 участников, 500 позиций, 500 выполненных компенсаций; сумма позиции/перевода до 1 млрд ₽. Большой суммарный долг разбивается на предложения в пределах лимита одной операции. Жадный план детерминирован, но не гарантирует минимального числа переводов. Данные локальные; ручные записи одинаковой суммы могут означать разные реальные переводы, поэтому их уникальность определяется ID, а не парой участников и суммой.

## История и резервные копии

Главный экран показывает сохранённые расчёты по дате последнего изменения. «Новый расчёт» открывает выбранный режим. Изменения участников, сумм, компенсаций и ошибочные черновики сохраняются сразу. Название можно изменить в карточке или редакторе; карточки позволяют открыть, дублировать, экспортировать и удалить расчёт. Удаление требует подтверждения и касается только выбранного расчёта. Сброс в редакторе очищает только текущий расчёт, сохраняя его ID и название.

«Экспорт всей истории» и «Экспорт расчёта» скачивают JSON формата `split-backup`, версия `5`: `exportedAt` и массив `records`. Каждая запись содержит `id`, `name`, `updatedAt` (UTC ISO 8601), `state` с данными выбранного режима и черновиками. Для позиций это `mode: "items"`, `expenses` (ID, title, amount, payerId, split, shares с personId/value) и `payments` (ID, fromId, toId, amount и необязательный operationId). В простом режиме `mode` отсутствует либо равен `simple`, прежняя модель сохранена. У копии конфликтующего импорта есть `importedFrom` для обнаружения повторов.

Импорт принимает схему 5, прежние копии схемы 4 и JSON-экспорт Split 3.0. До записи проверяются структура, версия, уникальность ID, даты, типы, суммы, индексы участников и лимиты. Предпросмотр показывает названия, даты, число участников и количество добавляемых/пропускаемых расчётов. Только «Подтвердить восстановление» записывает историю. Отмена и повреждённый файл ничего не меняют.

Восстановление объединяет данные: существующие записи не заменяются. Точные повторы пропускаются; при одинаковом ID с другим содержимым создаётся отдельная копия с новым ID. Повтор того же конфликтующего импорта также пропускается. Удалённую вручную запись можно восстановить повторным импортом. Лимиты: файл и сериализованная резервная копия истории до 10 МиБ, 500 расчётов, название до 120 символов, черновик суммы до 1000 символов. Реальная квота браузера может быть меньше. Пустой экспорт допускается и восстанавливается без добавления записей.

## Сохранение, миграция и безопасность

Имя ключа истории остаётся `split-history-v4`, версия документа теперь 5. Перед первой записью поверх схемы 4 её исходный документ сохраняется в `split-history-before-v5`; если архивирование невозможно, обновление не записывается. Старый клиент этапа 1 откажется писать неизвестную схему 5, что защищает позиции от незаметного удаления. Математический модуль простого режима `core.js` не изменён. При первом запуске содержимое `split-state-v2` переносится в расчёт «Расчёт из Split 3.0», включая ошибочные черновики и выполненные компенсации. При наличии истории запись добавляется к ней. Маркер `legacyMigrated` записывается вместе с историей, поэтому перезагрузка не дублирует миграцию. Более старые `people`, `transfers`, `target` тоже поддерживаются. Исходные ключи не удаляются и не перезаписываются. Тема остаётся в `split-theme`, поддерживается прежний ключ `theme`.

Если старая вкладка Split 3.0 продолжает работать после миграции, её последующие изменения остаются в старом ключе: для переноса экспортируйте JSON из той вкладки и импортируйте в 4.0. Автоматически повторять миграцию опасно из-за возможного дублирования или перезаписи истории.

При ошибке чтения запись блокируется, а «Скачать копию» отдаёт исходные байты для восстановления. Импорт в таком состоянии требует обычного предпросмотра и подтверждения; перед заменой повреждённый оригинал сохраняется в отдельном ключе `split-recovery-<UUID>`. Читаемые существующие расчёты добавляются к импорту. Если архивирование или запись не удались, исходный документ остаётся нетронутым. Архивы не удаляются автоматически.

При исчерпании квоты текущий ввод остаётся в редакторе и доступен в JSON-копии; переход к другому расчёту блокируется, чтобы не потерять несохранённый ввод. Событие `storage` и проверка снимка перед записью защищают от обычных конфликтов вкладок. Строго одновременные записи не имеют транзакционной гарантии: localStorage не предоставляет атомарную операцию compare-and-set. При конфликте скачайте текущую копию, перезагрузите страницу и импортируйте её с объединением.

Пользовательские названия и текст файлов выводятся через `textContent`/`value`, включая предпросмотр; HTML из JSON не исполняется. `innerHTML` используется только для констант SVG. CSP продолжает запрещать сторонние скрипты и объекты. Очистка данных сайта и приватный режим могут удалить историю: храните резервные копии вне браузера. JSON содержит имена и суммы открытым текстом, шифрование не применяется. Данные не отправляются во внешние сервисы.

## Граница платформы / будущий Capacitor

`history.js` содержит схему, миграцию, импорт/экспорт и `Store`, принимающий адаптер `getItem`/`setItem`. Модуль работает в браузере и Node.js, не зависит от DOM, файлового диалога или Capacitor. В `script.js` адаптер подключает localStorage, а интерфейс занимается навигацией и файловыми диалогами. `core.js` отвечает за простой режим, `items-core.js` — за денежные правила позиций и проведение компенсаций, `items-ui.js` — за редактор позиций. Эти модули не требуют Capacitor. Это позволяет отдельно заменить хранение и нативный файловый обмен; асинхронный нативный адаптер потребует асинхронной координации операций и сохранения контроля конфликтов. Сам Capacitor и нативные зависимости пока не добавлены.

## Структура

| Файлы | Назначение |
| --- | --- |
| `index.html`, `style.css` | Адаптивный интерфейс, темы, доступность, safe area и крупные элементы управления |
| `core.js` | Денежный модуль для браузера и CommonJS-тестов |
| `items-core.js`, `items-ui.js` | Математика позиций, проверка ссылок, защита операций и мобильный редактор |
| `history.js` | Схема истории, миграция, адаптер хранения и объединение резервных копий |
| `script.js` | История, навигация, форма, файловые диалоги и вывод результатов |
| `pwa.js`, `sw.js` | Регистрация, обновления и офлайн-кэш |
| `manifest.json`, `icons/` | Метаданные, обычные/maskable PNG, Apple Touch и SVG-исходник |
| `tests/` | Расчёты, браузер, обновление PWA и доступность |

## Автоматические тесты

Расчёты не требуют пакетов (Node.js 20+):

```sh
node tests/core.test.cjs
node --test --test-isolation=none tests/history.test.cjs tests/items.test.cjs
# Node.js 22+ — подробный вывод внутри процесса:
node --test --test-isolation=none tests/core.test.cjs
```

Браузерные инструменты — только для разработки. В подготовленной облачной среде уже есть Chromium и Playwright Core; axe-core установлен вне репозитория. На другой машине можно подготовить инструменты без изменения зависимостей приложения:

```sh
npm install --prefix /tmp/split-test-tools --ignore-scripts --no-audit --no-fund playwright-core@1.56.1 axe-core@4.11.0
export PLAYWRIGHT_MODULE=/tmp/split-test-tools/node_modules/playwright-core
export AXE_MODULE=/tmp/split-test-tools/node_modules/axe-core
export CHROMIUM_PATH=/usr/bin/chromium
```

При запущенном HTTP-сервере:

```sh
node tests/browser.cjs
node tests/accessibility.cjs
node tests/history-browser.cjs
node tests/items-browser.cjs
```

Другой адрес задаётся `SPLIT_URL`. Тест PWA поднимает собственный временный сервер и моделирует версии в памяти без изменения файлов:

```sh
node tests/pwa-update.cjs
```

Сканирование axe использует `bypassCSP` только для внедрения инструмента; функциональные тесты работают с действующей CSP. Результаты и ручной чек-лист — в [TESTING.md](TESTING.md).

## Обновление PWA

При каждом изменении оболочки увеличивайте версию `CACHE_NAME` в `sw.js`; обязательные ресурсы добавляйте в `SHELL`. Установка нового worker завершается только после полной загрузки ресурсов. До принятия обновления работает прежняя версия. Кнопка обновления не действует при ошибке сохранения. Автоматической перезагрузки редактируемой формы нет.

После активации удаляются прежние кэши Split, кэши других приложений сохраняются. Пользовательские данные находятся отдельно в localStorage. При изменении встроенного скрипта темы обновите SHA-256 в CSP `index.html`.
