# Split 3.0

Мобильное приложение для разделения общих расходов. Dark Glass, светлая/тёмная темы, локальное хранение, офлайн-PWA. HTML/CSS/JavaScript без фреймворков, сборки, серверной части и зависимостей приложения.

## Запуск

Из корня репозитория:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Для PWA на телефоне требуется HTTPS; localhost подходит для разработки. Поддерживается размещение в подпапке. Целевые браузеры: Safari/iOS 16+ и современные браузеры Android. Реальные устройства требуют ручной проверки.

На iPhone: Safari → «Поделиться» → «На экран “Домой”». На Android: меню Chrome → «Установить приложение» / «Добавить на главный экран». Офлайн доступен после успешной первой загрузки и установки service worker. Шрифты системные, все ресурсы локальные.

## Модель расчёта

- Внесённые суммы — оплаты общих расходов. Пустая цель равна сумме внесённого. Явный ноль отличается от пустого поля.
- Переводы — **уже выполненные компенсации**. Если Борис должен Анне 500 ₽ и перевёл 200 ₽, остаётся 300 ₽. Выполненная компенсация уменьшает долг отправителя и сумму к получению адресата.
- Все расчёты — в целых копейках. Неразделимый остаток распределяется первым участникам по одной копейке; сумма долей совпадает с расходами. Сводка показывает диапазон долей, карточки — точные значения.
- Недобор и излишек относительно цели представлены отдельными операциями с общей кассой. Детерминированный план погашает балансы, но не гарантирует математически минимальное число переводов.
- Ввод принимает точку/запятую и до двух дробных знаков. Лимиты: 1 млрд ₽ на сумму, 100 участников, 500 переводов. Неверный ввод выделяется, копирование блокируется, сводка явно показывает последние корректные значения.

## Сохранение и безопасность

Каждый ввод сохраняется сразу в `localStorage` (`split-state-v2`), в том числе неверные черновики. Переключение темы не пересоздаёт форму. Миграция поддерживает прежние ключи `people`, `transfers`, `target`, а также тему `theme`; старые ключи сохраняются для восстановления.

При повреждённых данных запись не перезаписывается, предлагается скачать исходную копию. При отказе localStorage или обнаружении конфликта вкладок показывается постоянное предупреждение. Проверяются событие `storage` и текущее значение перед записью. Строго одновременные записи не имеют транзакционной гарантии: localStorage не предоставляет блокировок.

«Скачать копию» экспортирует JSON; импорта в интерфейсе пока нет. Очистка данных сайта, приватный режим или действия браузера могут удалить локальные данные, поэтому нужны резервные копии. Данные не отправляются во внешние сервисы.

Пользовательский текст выводится через `textContent`/`value`. `innerHTML` используется только для констант SVG. CSP разрешает локальные скрипты и единственный встроенный скрипт темы по SHA-256; сторонние скрипты и объекты запрещены.

## Структура

| Файлы | Назначение |
| --- | --- |
| `index.html`, `style.css` | Адаптивный интерфейс, темы, доступность, safe area и крупные элементы управления |
| `core.js` | Денежный модуль для браузера и CommonJS-тестов |
| `script.js` | Форма, валидация, восстановление, сохранение и вывод результатов |
| `pwa.js`, `sw.js` | Регистрация, обновления и офлайн-кэш |
| `manifest.json`, `icons/` | Метаданные, обычные/maskable PNG, Apple Touch и SVG-исходник |
| `tests/` | Расчёты, браузер, обновление PWA и доступность |

## Автоматические тесты

Расчёты не требуют пакетов (Node.js 20+):

```sh
node tests/core.test.cjs
# Node.js 22+ — подробный вывод внутри процесса:
node --test --test-isolation=none tests/core.test.cjs
```

Браузерные инструменты — только для разработки. В подготовленной облачной среде уже есть Chromium и Playwright Core; axe-core установлен вне репозитория. На другой машине можно подготовить инструменты без изменения зависимостей приложения:

```sh
npm install --prefix /tmp/split-test-tools --ignore-scripts --no-audit --no-fund playwright-core@1.56.1 axe-core@4.11.0
export PLAYWRIGHT_MODULE=/tmp/split-test-tools/node_modules/playwright-core
export AXE_MODULE=/tmp/split-test-tools/node_modules/axe-core
export CHROMIUM_PATH=/usr/bin/chromium
```

При запущенном HTTP-сервере:

```sh
node tests/browser.cjs
node tests/accessibility.cjs
```

Другой адрес задаётся `SPLIT_URL`. Тест PWA поднимает собственный временный сервер и моделирует версии в памяти без изменения файлов:

```sh
node tests/pwa-update.cjs
```

Сканирование axe использует `bypassCSP` только для внедрения инструмента; функциональные тесты работают с действующей CSP. Результаты и ручной чек-лист — в [TESTING.md](TESTING.md).

## Обновление PWA

При каждом изменении оболочки увеличивайте версию `CACHE_NAME` в `sw.js`; обязательные ресурсы добавляйте в `SHELL`. Установка нового worker завершается только после полной загрузки ресурсов. До принятия обновления работает прежняя версия. Кнопка обновления не действует при ошибке сохранения. Автоматической перезагрузки редактируемой формы нет.

После активации удаляются прежние кэши Split, кэши других приложений сохраняются. Пользовательские данные находятся отдельно в localStorage. При изменении встроенного скрипта темы обновите SHA-256 в CSP `index.html`.
